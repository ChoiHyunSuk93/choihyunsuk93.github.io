한국어

1. 개인정보처리자와 적용 범위

Pond Life는 최현석이 제공하는 모바일 게임입니다. 개발자는 Pond Life의 개인정보처리자이며, 본 방침은 기기 내 저장, 선택적 Apple·Google 로그인, 클라우드 저장, 친구·방문·알림 기능, 원격 설정 및 광고 SDK에서 처리되는 정보를 설명합니다.

게스트는 계정용 게임 진행, 프로필, 친구 및 방문 정보를 Cloud Firestore에 업로드하지 않습니다. 다만 게스트에게도 앱 버전·점검·공지 확인을 위한 Firebase Remote Config와 광고·동의 SDK 통신이 발생할 수 있습니다.

4. 다른 이용자에게 보이는 정보

친구 요청 수신자는 수락 전에도 요청자의 닉네임과 개구리 레벨·단계 요약을 볼 수 있습니다. 상호 수락된 친구는 상대의 프로필(닉네임, 친구 코드, 개구리 레벨·단계 및 갱신 정보)과 방문용 마을 스냅샷을 단건 조회할 수 있습니다. 친구 목록 전체 검색과 공개 프로필 목록은 제공하지 않으며, 방문 중 이동·상호작용 결과는 방문한 친구의 서버 저장이나 재화에 반영되지 않습니다.

6. 파기와 계정 삭제

전자적 정보는 복구하기 어려운 방식으로 삭제합니다. 앱 삭제는 기기 내 데이터만 삭제할 수 있으며 서버 계정 데이터는 자동으로 삭제하지 않습니다. 서버 데이터까지 삭제하려면 앱을 삭제하기 전에 게임 설정의 계정 삭제를 사용하거나 아래 연락처로 요청해야 합니다.

앱 내 계정 삭제가 완료되면 전송을 중지하고 클라우드 저장, 친구 관계, 방문 스냅샷, 알림 등록과 발송 기록, 소셜 프로필·친구 코드, Firebase 인증 계정 및 해당 기기의 계정별 작업본을 순차적으로 삭제합니다. Apple 로그인 계정은 지원되는 삭제 흐름에서 Apple token 폐기도 요청합니다. 서버 trigger와 제공자 백업 삭제는 비동기로 마무리될 수 있습니다.

7. 처리 위탁, 외부 서비스 및 국외 이전

개발자는 서비스 제공을 위해 아래 사업자에게 처리를 위탁하거나 해당 사업자의 서비스를 이용합니다. Pond Life의 Cloud Firestore와 Cloud Functions 데이터 리전은 대한민국 서울(asia-northeast3)로 설정되어 있습니다. Firebase Authentication은 미국에서 처리되고, FCM·Remote Config·App Check 등 글로벌 서비스 및 Apple·Google 서비스는 대한민국 밖의 제공자 인프라에서도 처리될 수 있습니다.

국외 이전은 이용자가 선택한 계정·클라우드·소셜·알림·광고 서비스를 제공하기 위한 계약 이행상 처리위탁·보관과, 적용되는 경우 이용자의 동의를 근거로 합니다.

8. 광고와 자동 수집 장치

Pond Life는 보상형 광고 제공을 위해 Google AdMob, Google Mobile Ads SDK 및 UMP를 사용합니다. 앱의 광고 요청은 비개인화 광고로 고정되고 publisher first-party ID 사용은 비활성화됩니다. Google 및 광고 파트너는 광고 제공, 빈도 제한, 측정, 부정 사용 방지, 진단 및 성능 개선을 위해 제2조의 기술·광고 정보를 처리할 수 있습니다.

앱 시작 시 UMP가 지역별 개인정보 메시지와 광고 요청 가능 여부를 확인합니다. 다시 선택할 수 있어야 하는 경우 게임 설정의 개인정보 선택에서 선택 화면을 열 수 있습니다. 앱은 Apple App Tracking Transparency 권한을 요청하지 않으며 IDFA를 이용한 앱·웹사이트 간 추적을 하지 않습니다. UMP 광고 선택은 계정·클라우드 저장 처리에 대한 동의와 별개입니다.

Firebase SDK는 Firebase installation ID 등 자동 생성 식별자와 기술 정보를 사용할 수 있습니다. 이 웹페이지는 언어 선택을 브라우저 localStorage에만 저장하며 개발자 서버로 전송하지 않습니다. Google의 광고 데이터 처리는 Google 광고 기술 안내를 따릅니다.

9. 제3자 제공

개발자는 개인정보를 판매하지 않으며, 이용자의 별도 동의 또는 법률상 근거 없이 제3자에게 제공하지 않습니다. 제4조의 친구 간 표시, 제7조의 위탁·외부 서비스 처리 및 법령에 따른 요청은 이 원칙에 따른 범위에서 처리됩니다.

10. 이용자와 법정대리인의 권리

이용자 또는 법정대리인은 개인정보의 열람, 정정, 삭제, 처리정지 및 동의 철회를 요청할 수 있습니다. 닉네임은 소셜 화면에서 정정하고, 친구 관계는 친구 삭제로 종료하며, 원격 알림과 광고 개인정보 선택은 게임 설정에서 변경할 수 있습니다. 전체 계정 데이터는 게임 설정의 계정 삭제로 삭제할 수 있습니다.

앱에 접근할 수 없거나 추가 확인이 필요한 경우 pondlife.support@gmail.com으로 요청하십시오. 본인 또는 정당한 대리인 확인에 필요한 최소 정보만 요청할 수 있으며, 법령이 정한 기간 안에 처리 결과를 안내합니다.

11. 안전성 확보 조치

개발자는 전송 구간 암호화, Firebase Authentication 기반 계정 분리, Firestore 보안 규칙, App Check, 서버 전용 알림 token·발송 기록, 최소 권한 접근을 적용합니다. 전체 저장은 본인만 읽고 쓸 수 있으며 친구는 수락된 관계에서 프로필과 방문용 최소 스냅샷만 조회할 수 있습니다.

12. 아동의 개인정보

Pond Life는 일반 이용자를 대상으로 하며 아동을 주 이용자로 설계하지 않았습니다. 만 14세 미만 아동의 개인정보를 법정대리인의 동의 없이 처리한 사실을 알게 되면 확인 후 해당 정보를 삭제합니다. 법정대리인은 제10조의 권리를 행사할 수 있습니다.

13. 개인정보 보호책임자와 문의

개인정보 보호책임자는 개발자 최현석입니다. 개인정보 처리, 권리 행사, 피해 구제 또는 본 방침에 관한 문의는 pondlife.support@gmail.com으로 연락해 주십시오.

본 방침은 앱 기능, 외부 SDK, 처리 사업자, 관련 법령 또는 정책 변경에 따라 수정될 수 있습니다. 중요한 변경이 있는 경우 본 페이지의 시행일을 갱신하고 필요한 방법으로 알립니다.

English

1. Controller and Scope

Pond Life is a mobile game provided by Hyun Suk, Choi. The developer is the controller of personal information handled by Pond Life. This Policy covers on-device storage, optional Apple and Google sign-in, cloud save, friends, visits, notifications, Remote Config, and advertising SDKs.

Guests do not upload account-based game progress, profiles, friend relationships, or visit data to Cloud Firestore. Remote Config requests for app version, maintenance, and notices, as well as advertising and consent SDK communications, may still occur for guests.

2. Information Processed and How It Is Collected

Category Information Collection or generation
On-device game data Game progress, currency, items, inventory and placement, owned animals, frog growth, wishes, tutorial, rewarded-ad records, and app settings Generated and stored on the device during gameplay
Account and authentication Firebase UID, sign-in provider (Apple or Google), email and name if supplied by the provider, authentication credentials and tokens. The developer does not directly collect or store passwords. Processed by the selected provider and Firebase Authentication when the user chooses Apple or Google sign-in
Cloud save Full game progress linked to the account UID, save schema and revision, and save time Generated and transmitted when an authenticated device backs up to or restores from Cloud Firestore
Profile and friends Nickname, eight-character friend code, frog level and stage, peer UID, request code and status, requester progress summary, and creation or update times Entered or generated when an account is created or a nickname or friend relationship is managed
Friend-visit snapshot Nickname, frog level and stage, collection-reward background status, completed placed-object type, position, direction and placement area, and update time Generated for friend visits after a signed-in user's latest cloud save succeeds
Friend-request notifications Installation identifier, FCM registration token, platform, locale, app version, registration time, delivery event ID, sender and receiver UIDs, delivery status, attempt counts, and processing times Generated automatically when an authenticated user enables remote notifications and a friend request is created
Technical and advertising data IP address, user agent, device, app and installation identifiers, app-integrity information, Remote Config request information, advertising identifiers, ad impressions and interactions, diagnostics, performance data, and approximate location inferred from IP, as disclosed by the applicable SDK May be processed automatically when Firebase, Apple, Google sign-in, APNs, Google Mobile Ads, or UMP services are used

Pond Life does not offer contact-based friend discovery, chat, nickname search, or precise-location collection.

3. Purposes of Processing

  • Apple or Google authentication, session restoration, and account security
  • On-device saves, account cloud backup and restore, and cross-device conflict prevention
  • Nicknames, friend-code issuance, friend relationships, and read-only friend-village visits
  • Friend-request system notifications, duplicate-delivery prevention, and invalid-token cleanup
